# Hardware and software requirements
- **CUDA**>=12.8 : Tested on an NVIDIA RTX4070 with driver 580.178.04 / CUDA 13.0 and on an NVIDIA RTX5090 with 570.211.01 / CUDA 12.8
- **8Gb VRAM**
- **Ubuntu**
- **Anaconda**
- **Python**>= 3.10

# Installation
### 1. create environment
``` bash
conda create --name refiner python=3.10
conda activate refiner
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
pip install -e . --no-build-isolation
```

### 2. Install MonoGS Rasterizer
``` bash
pip install third_party/MonoGS/simple-knn --no-build-isolation
pip install third_party/MonoGS/diff-gaussian-rasterization --no-build-isolation
```

# Data
Our dataset is available [here](https://cloud.minesparis.psl.eu/index.php/s/Qr3Urhe0Q9CXrYD). It contains finely-registered images (164) into heterogeneous point cloud scenes (29). It is organized as follows:
```
<set>
└── <scene>
    ├── cameras
    │   ├── <name>.yaml
    │   └── ...
    ├── images
    │   ├── <name>.png
    │   └── ...
    ├── eval
    │   ├── <name>.json
    │   └── ...
    ├── pc.ply
    ├── (optional) seg
    │   └── <name>.png
    └── (optional) raw
        ├── calibration
        │   ├── calibration.json
        │   └── <name>.json
        ├── cameras
        └── images
```
For each set (Tanks and Temples, ETH3D, ...) and scene (Meetingroom, Courtyard, ...) you will find the point cloud (_pc.ply_) camera parameters (_cameras_) as yaml files, the different images (_images_) and the fine correspondences (_eval_) used for evaluation. In the case of Tanks And Temples and nuScenes you will additionally find the raw registration data extracted from the base dataset (_raw/cameras_ and (_raw/images_)) as well as our manual calibration data (_calibration_). For the CARLA set we fournish as well the free segmentation data generated by the simulator for both the images (_seg_) and the point cloud (_seg_ channel in _pc.ply_) with matching cityscape classes.

Once downloaded, please export the required environment variable
``` bash
export REFINER_DATA_DIR=<path>
```
# Running the main script
1. Configure main.yaml or use and included list of yaml files in the config/components folder. Please refer to the main.yaml file or the *refiner/utils/config_types.py* for an exhaustive list of the available configuration.
```yaml
include: 
  - data.yaml
  - camera.yaml
  - ...
```

2. You may run the main.py script using. If you have configured the Rerun saver, a widow should popup.
```bash
python main.py \
  --set TanksAndTemples \
  --scene Church \
  --img_idx 1
```

3. You can also customize the config on the fly using the *--cfg* option:
```bash
python main.py \
  --set TanksAndTemples \
  --scene Church \
  --img_idx 1 \
  --cfg data.pc_subsample_factor
```

# Running the benchmark experiments
You can use the defined configuration files in "config/experiments" to run the experiment setup on our data, for instance using 
```bash
python main.py \
  --set nuScenes \
  --cfg_file config/experiments/reflectivity.yaml \
  --out_dir output/experiments/intensity \
  --repeat 5 
```
After each experiment on several sets you should run the compile_results.py script, which gathers all metrics from each registration, with 

```bash
python compile_results.py \
  --out_dir output/experiments/intensity
```

# MatchAnything
You may find third_party/MatchAnything the code from the [MatchAnything](https://github.com/zju3dv/MatchAnything) project which is used to estimate a better initialization to ReFineR. For setting it up, please download the weights from [this page](https://huggingface.co/spaces/LittleFrog/MatchAnything/blob/main/imcui/third_party/MatchAnything/README.md) and export the MATCHANYTHING_WEIGHTS_DIR environment variable
```bash 
export MATCHANYTHING_WEIGHTS_DIR=<path>
```

from the config you can now change the corresponding fields to true: 
```yaml
matchAnything_init: True
matchAnything_init_gs: True
```

# Marigold
You can experiment with generating synthetic channels using [Marigold](https://www.obukhov.ai/marigold).
1. Download the Marigold weights and put it in the weights/Marigold folder (check [the Marigold repository](https://github.com/prs-eth/Marigold?tab=readme-ov-file#-checkpoint-cache))
2. Build the docker image from docker/Marigold with
```bash
$ docker image build -t marigold .
```
3. Run the marigold.py script with 
```bash
python marigold.py \
--set TanksAndTemples \
--scene Church \
--models normals iid 
```
- This will create an output/precomp/\<set>/\<scene> folder with Marigold outputs. You can specify another folder using the _out_dir_ option
- You can specify which model(s) to use (depth, normal, iid)

4. Update the configuration to select the synthetic channels under the *loss* field 
```yaml
loss:
  grad:
    channels: 
      - comp: [nx, nx]
        weight: 1
      - comp: [ny, ny]
        weight: 1
      - comp: [nz, nz]
        weight: 1
      - comp: [g, dn]
        weight: 1
      - comp: [g, mat]
        weight: 1
      - comp: [g, alb]
        weight: 1
    weight: 1
```

(nx, ny, nz for normals, dn for depth, mat and alb for material and albedo)
